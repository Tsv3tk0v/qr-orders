# QR поръчки

Платформа за поръчки без плащане: QR от телефона и/или киоск на щанда, кухненски таблет, табло „Готвят се / Готови“, админ панел. Много бизнеси и обекти, всеки на свой поддомейн. Български и английски.

## Инсталация (без ИТ познания)

На сървър с Ubuntu:

```
git clone https://github.com/tsv3tk0v/qr-orders.git && cd qr-orders && sudo bash install.sh
```

Подробно, стъпка по стъпка: **[docs/INSTALL.md](docs/INSTALL.md)**. Управление след това: `qr help`.

## Какво има
- **Клиент** (`https://<бизнес>.<домейн>`): меню с филтри, добавки и „без“, количка, статус на живо. Теми „Светла“ и „Класическа“.
- **Кухня** (`/kitchen`), **табло** с въртящ се QR (`/board`), **киоск** с бележка ESC/POS (`/kiosk`) — на сдвоени таблети.
- **Админ** (`/admin`): меню, филтри, компоненти, импорт CSV/XLSX + SFTP, външен вид, обекти и устройства, потребители с роли и двуфакторен вход, черен списък, журнал, отчети, дневен имейл.
- **Платформа** (`https://admin.<домейн>`): първоначална настройка и бизнеси.
- **Android обвивка** (`android/`): цял екран, автостарт, печат по LAN. APK се строи в GitHub Actions.

## Структура
- `apps/api` — сървър: Node.js (TypeScript), Fastify, PostgreSQL с RLS, SSE
- `apps/web` — уеб екраните (React + Vite)
- `packages/shared` — общи правила (статуси, цени, марка, роли)
- `db/migrations` — схема на базата
- `deploy/`, `install.sh`, `qr` — инсталация с Docker и Caddy (автоматичен HTTPS)
- `android/` — приложение-обвивка за устройствата
- `docs/` — решения, предаване, инсталация, мокъпи

## Разработка
1. PostgreSQL 16. Веднъж като администратор: `psql -f db/roles.sql`, после създайте базите `qr` и `qr_test` със собственик `qr`.
2. `cp .env.example .env`.
3. `pnpm install`, `pnpm db:migrate`, `pnpm test`.
4. `pnpm --filter @qr/api dev` и `pnpm --filter @qr/web dev`, после отворете `http://admin.lvh.me:5173` (с `BASE_DOMAIN=lvh.me` и `SETUP_CODE` в `.env`).

Приложението се свързва като `qr_app` (без права да заобикаля RLS); миграциите — като `qr`. Всяка заявка минава през `withScope` (`apps/api/src/db/pool.ts`), който задава бизнеса за RLS.

Поддомейни: бизнес — `<бизнес>.<домейн>`, обект — `<бизнес>--<обект>.<домейн>` (едно ниво, за да го покрива сертификатът).
